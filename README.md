# Blood Cell Classification (CMP6232)

EfficientNet-B0 (vs MobileNetV3-Small, DenseNet121) transfer-learning classifier
for RBC / WBC / Platelet crops, built from the TXL-PBC dataset.

## Folder structure

```
blood-cell-classification/
├── data/
│   ├── raw/                # put the downloaded TXL-PBC repo contents here
│   │   ├── images/         # source microscopy images
│   │   └── labels/         # YOLO-format .txt annotations (one per image)
│   └── processed/          # generated by crop_dataset.py — do not edit by hand
│       ├── train/{RBC,WBC,Platelet}/
│       ├── val/{RBC,WBC,Platelet}/
│       └── test/{RBC,WBC,Platelet}/
├── configs/
│   └── config.yaml          # all paths/hyperparameters in one place
├── src/
│   ├── crop_dataset.py      # step 1: turns raw images+labels into cropped, split, class-folder dataset
│   ├── dataset.py           # PyTorch Dataset + transforms + weighted sampler
│   ├── model.py              # builds EfficientNet-B0 / MobileNetV3-Small / DenseNet121
│   ├── losses.py             # class-weighted CE and focal loss (effective-number weighting)
│   ├── train.py               # training loop, checkpointing on best val macro-F1
│   ├── evaluate.py            # test-set macro P/R/F1 + confusion matrix
│   └── utils.py
├── outputs/
│   ├── checkpoints/           # saved model weights (best_<model_name>.pt)
│   ├── logs/                   # per-epoch CSV logs
│   └── results/                 # confusion matrices, comparison table
└── requirements.txt
```

## Workflow

1. **Get the data.** Clone/download TXL-PBC and place its images under
   `data/raw/images/` and its YOLO label files under `data/raw/labels/`.
   Keep whatever train/val/test image-list files TXL-PBC ships with — you'll
   point `crop_dataset.py` at them so crops from the same source image stay
   in the same split (no leakage).

2. **Set up the environment and GPU.**
   This project is intended for Python 3.11. Using Python 3.14 on Windows often
   resolves to the Microsoft Store alias instead of the actual interpreter, which
   causes CUDA/PyTorch setup issues and prevents GPU detection.

   Recommended Windows setup:
   ```powershell
   # Use the real Python 3.11 interpreter explicitly if the default 'python' alias points to 3.14
   & "C:\Users\MSI\AppData\Local\Programs\Python\Python311\python.exe" -m venv venv
   .\venv\Scripts\Activate.ps1
   python -V
   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt
   ```

   If you are using a GPU machine, verify CUDA first before training:
   ```powershell
   python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'No GPU')"
   ```
   Expected output:
   ```text
   True
   NVIDIA GeForce RTX 3060
   ```
   If it prints `False` or `No GPU`, the issue is not in the project code — it is
   the local Python/CUDA/driver setup.

   For Windows with NVIDIA GPUs, install the NVIDIA driver and then install the
   CUDA-enabled PyTorch build:
   ```powershell
   python -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
   ```

3. **Crop the dataset** (raw images + bounding boxes → per-class image crops):
   ```bash
   python src/crop_dataset.py --config configs/config.yaml
   ```

4. **Sanity-check class counts** printed at the end of step 3 against the
   expected ~16,302 RBC / ~1,298 WBC / ~543 Platelet — if they're off,
   check the label parsing before training anything.

   Important: the TXL-PBC YOLO annotations use class index order
   `0=WBC`, `1=RBC`, `2=Platelet`. Keep `configs/config.yaml` in the same
   order, otherwise crops are written into the wrong class folders and the
   model learns the mislabeled classes.

5. **Train one model at a time:**
   ```bash
   python src/train.py --config configs/config.yaml --model efficientnet_b0
   python src/train.py --config configs/config.yaml --model mobilenet_v3_small
   python src/train.py --config configs/config.yaml --model densenet121
   ```
   Each run logs per-epoch loss/macro-F1 to `outputs/logs/`, saves the best
   checkpoint (by validation macro-F1) to `outputs/checkpoints/`, and prints
   training time + peak GPU memory at the end.

6. **Evaluate on the test set:**
   ```bash
   python src/evaluate.py --config configs/config.yaml --model efficientnet_b0
   ```
   This writes a normalised confusion matrix and a macro P/R/F1 report to
   `outputs/results/`.

7. **Build the comparison table** across all three models (accuracy/F1 vs
   params vs training time/memory) from the three `outputs/results/*.json`
   files — this is what goes into your report's Proposed Model section as
   the empirical justification for choosing EfficientNet-B0.

8. **Write up.** Pull the confusion matrices and metrics into the report,
   and use the WBC/Platelet recall numbers specifically when discussing the
   ethics/clinical-risk angle (a missed WBC matters more than a missed RBC).

## Notes
- Class imbalance handling (weighted sampler + effective-number class
  weights + minority-targeted augmentation) is already wired into
  `dataset.py` and `losses.py` — see the comments there before changing
  anything.
- Checkpoint selection is keyed on macro-F1, not accuracy, on purpose.
